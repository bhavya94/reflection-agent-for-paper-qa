How PR #6 finds the evidence: BM25, step by step

The agent answers a question about a paper. It does not read the whole paper. It reads only the paragraphs that a search step finds. PR #6 builds that search step and measures how often it finds the right paragraphs.

Pull request #6 · Written explainer

Why the project needs this step

  1. Cost: the model reads about 20 paragraphs, not the full paper. Every later model call is cheaper.
  2. A ceiling: if the search misses the evidence, the model cannot answer correctly. It can only guess.
  3. Diagnosis: we measure the search on its own. Then a wrong answer is either a search miss or a model mistake, never a mix.

BM25 on three real questions

BM25 is a keyword search score. It gives each paragraph points for each question word it contains. Pick a question. Then follow the three steps.

Step 2. Weigh each word

A word that is in few paragraphs of this paper is a strong signal. A word that is in most paragraphs is weak. This weight is the IDF (inverse document frequency).

Step 3. Score and rank the paragraphs

Each paragraph gets the sum of its word scores. A word scores more when it appears more often, but each extra time adds less. Long paragraphs get a small penalty, so they do not win only because they are long. Click a row to see the paragraph and the arithmetic.

It uses about 11,700 characters of the paper (about 2,900 tokens). Example 3 shows what it misses: evidence that uses different words.

The formula

score(paragraph) = Σword IDF(word) × tf / (tf + k1 × (1 − b + b × length / average length))

tf is how many times the word is in the paragraph. k1 = 1.5 controls how fast extra repeats stop adding points. b = 0.75 controls the length penalty. IDF = ln(1 + (N − n + 0.5) / (n + 0.5)), with N paragraphs in the paper and n paragraphs that contain the word. These are the defaults of the bm25s library (Lucene variant). The numbers on this page come from that formula. Their sums match the library scores to 0.0000001.
