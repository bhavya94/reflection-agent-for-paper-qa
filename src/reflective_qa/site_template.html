An experiment with Claude agents · 200 questions about research papers

Does a review step make an AI agent answer research questions better?

Not on average. A reviewer checks the agent's answer, and the agent revises it once. The reviewer fixes answers where the agent gave up too early. It also rewrites good answers into worse ones. The two effects cancel.

The task

A person asks a question about one research paper. The AI must answer from the paper's text, and name the paragraphs that support its answer. If the paper does not contain the answer, the correct reply is “Unanswerable”.

The questions come from QASPER, a public dataset of questions about natural language processing (NLP) papers. Experts read each full paper and wrote the reference answers. Some questions have two or more expert answers, and the experts don't always agree. We use questions, picked at random from the dataset's development split. 14.5% of them have an expert who answered “Unanswerable”.

The agent

The agent has a writer model and a review step. It runs four steps for each question:

1Search

Keyword search (BM25) picks the paragraphs that best match the question. The larger model gets 20 paragraphs. The smaller model gets 5.

2Answer

The writer model gives a short answer and the IDs of the paragraphs it used.

3Review

The review step checks the answer against the same paragraphs. It lists problems, or passes the answer.

4Revise once

If the review found problems, the writer gets them and answers again. If not, the first answer stays.

A reviewer model checks each answer for seven problems:

  • It says “Unanswerable”, but the paragraphs contain the answer.
  • It gives an answer, but the paragraphs don't contain one.
  • It is wrong, or misses part of the question.
  • It makes a claim the cited paragraphs don't support.
  • It cites the wrong paragraphs.
  • It is longer than needed.
  • It doesn't answer a yes/no question with Yes or No.

Free code checks catch some of these without a model: long answers, citation errors, and the yes/no format.

We tried six versions of the review step. Claude Sonnet 5.5 is the larger model. Claude Haiku 5.5 is smaller and cheaper, and it gets fewer paragraphs, so its first answers have more to fix.

The last two versions are almost the same, because the code checks flag almost no Haiku answers. The gap between their results shows how much the scores move by chance.

How we score

Answer score (answer-F1). A number from 0 to 1 for each answer. It measures how many words the answer shares with the expert answer. Extra words lower it, and missing words lower it. Small words like “the” and punctuation don't count. When experts disagree, the best match counts. We report the average over all questions.

So a correct answer in different words can score low. Use the scores to compare versions on the same questions.

Evidence score (evidence-F1). The same idea for citations: the overlap between the paragraphs the AI cited and the paragraphs the experts marked. Says “Unanswerable” is the share of questions where the AI gave up.

Change and 95% interval. The change is the average answer score after review minus the average before, on the same questions. To see how much of the change is luck, we resample the questions 5,000 times (a paired bootstrap). If the interval includes zero, the data can't tell the change from chance.

Where the change comes from

A review can change an answer in three ways. In all four versions with a reviewer model, fixing a wrong “Unanswerable” raised the score. Rewording an answer lowered it in three of those four. A new “Unanswerable” always lowered it. Code checks only shortened answers, which raised the score a little. The parts add up to the total change, shown by the tick.

Limits

  • The answer score rewards shared words, so it can miss a correct answer in other words.
  • We changed the revise prompt after a 20-question pilot, and those 20 questions are part of the sample.
  • One review round, one dataset, two models.
